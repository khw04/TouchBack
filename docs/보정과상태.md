# 보정 후보와 화구 상태 (C-KH-05 준비 구현)

## 구현과 실측의 구분

현재는 개발용 RMS 자료로 보정 후보를 생성하고 Mock에서 단계 추적·재동기화·재보정을 실행하는 소프트웨어 구현이다. 실측 데이터, 독립 평가, live 활성화, 제조사 2종/냄비 3종·동시 2화구 검증은 미완료다. C-KH-05 전체 본선 목표를 완료했다고 보고하지 않는다.

## 오프라인 보정 후보

`backend/app/calibration/fitting.py`의 fit_candidate는 DevelopmentSample 배열을 받아 draft CalibrationCandidate를 만든다.
입력에는 trial_id, split, 독립 표시 단계와 정답 출처, 인덕션 기종, 냄비, 설치 ID, DeviceObservation이 필요하다. 이 입력은 Agent가 읽는 관측과 분리한다.
평가 split, 중복 trial/관측, 품질 이상/샘플 부족, 설치·세션·단위·방법/샘플링 혼합, 단계당 3개 미만을 거부한다. 3개는 개발용 최소 조건이며 실제 정확도를 입증하는 표본 수가 아니다.
실물의 표시 단계 정답은 manual_display/video_display로 수집한다. mock_fixture 정답으로 live 후보를 만들 수 없다.
단계별 min/max RMS에 호출자가 정한 margin을 적용한다. 겹침·역순 등 RMS만으로 구분되지 않으면 후보 생성에 실패한다. 고주파/듀티 등 추가 특징은 v0.3 계약과 실측 후 확장해야 한다.

backend 폴더에서 다음 명령을 사용한다. 입력 파일은 위 모델의 JSON 하나+LF이며, 아직 실제 개발 자료는 없다.

```powershell
..\.venv\Scripts\python.exe -m app.calibration.cli --input development.jsonl --output candidate.json --calibration-id device-install-v1 --margin 0
```

기존 출력 파일을 덮어쓰지 않는다. 후보는 source와 draft 상태, 기종/냄비/설치/세션·측정 설정·개발 trial ID를 보존한다. 후보 생성은 실측 검증/운영 승인/LLM 판정이 아니다.

## 화구별 상태와 재보정

`backend/app/observations/state.py`의 StateTracker는 right/left의 ZoneState를 별도로 보관한다. 동시 조작을 지원하는 실행 API가 아니다.
상태는 needs_calibration → activate_mock → needs_baseline → 유효 관측 observe → ready다.
activate_mock는 동일 화구/설치의 Mock 후보만 받는다. live 후보는 실측 검증 절차와 시간 매핑 근거가 준비될 때까지 활성화하지 않는다.
observe는 장치/부팅 세션/출처/보정 ID, 품질·시계·신선함, 샘플링 설정을 검사해 단일 단계 서명에 속하는 경우에만 level을 기록한다.
Agent는 어댑터의 품질을 StateTracker.handle_integrity에 전달해야 한다. 전체 장치 오류는 모든 화구를, 화구별 오류는 지정 화구만 무효화한다.
부팅 세션/설정 변경, 끊김·포화, 오래된 관측, 판별 불가 시 기존 단계·기준·보정을 폐기한다. 스냅샷은 level=null과 이유를 반환한다. 다른 화구의 관측은 해당 화구 상태를 지우지 않는다.
재보정은 새 후보를 생성·선택하고 새 기준을 다시 수집하는 과정이다. 숫자를 자동으로 고쳐 정상으로 위장하지 않는다. 동일 오류 관측의 반복만으로 ready를 유지하지 않는다.

## 검증 Skill 연결

ZoneState.verify는 현재 Mock 단계 서명으로 기준/목표 단계의 증가량 구간을 구성하고 C-KH-03 verify_intent에 위임한다. 기존 품질·시간·세션·조작 검사는 유지한다.
Mock 기본 운영값은 변화 없음 2, 증가 최소 5, 후속 길이 500ms, 기준 신선함 500ms, 후속 신선함 5000ms, 수신 지연 4000ms다. 실측값/제품 보장으로 인용하지 않는다.
검증 결과만으로 현재 단계를 자동 갱신하지 않는다. 다음 유효 관측을 observe로 확인한다. 다음 조작에는 새로 수집한 신선한 기준이 필요하다.
보정 해상도가 운영 기준보다 부족하면 uncertain/calibration_resolution_insufficient다. live/replay는 Mock 단계 검증으로 성공하지 않는다.

## Skill과 다음 의존 작업

- auto-calibration → fit_candidate / 오프라인 CLI. 실측 후보는 draft로만 생성.
- state-resynchronization → ZoneState.observe. 현재 Mock 재동기화 검증.
- sensor-recalibration → invalidate → 후보 생성 → activate_mock → 새 observe. 현재 Mock 재개 검증.

skills/의 각 SKILL.md에서 실제 함수와 실패 처리·실행 방법을 확인한다. LLM Tool 등록·복구 실행은 윤도훈 담당이다.
임민혁/차우진은 실제 기종·냄비·설치와 독립 정답의 개발/평가 샘플, 신호 특징 및 시계 오차 근거를 제공해야 한다. 입력 계층은 실제 live 매핑을 unverified로 유지한다. 이 자료 없이 live 성공 판정을 활성화하지 않는다.
