# 구현 시작 기준

2026-10-05. '바로 구현을 시작'하기 위해 정한 기본 구현 경로다. 부품·실측·자격증명 확보가 끝났다는 뜻은 아니다.
사용자가 직접 지정한 스택은 아니며 이 문서의 기본값을 사용한다. 변경 필요 시 이유와 영향을 PR로 기록한다.

## 기본 선택

- Python + FastAPI 백엔드, pytest 검증. 권희원이 초기 환경에서 호환 버전을 확인하고 의존성을 고정한다.
- 첫 화면은 HTML/CSS/JavaScript 정적 페이지이며 백엔드가 제공한다. P0 음성 안내는 김민찬이 브라우저 TTS/재청취로 구현하고 윤도훈이 안내 텍스트를 제공한다. 음성 입력은 후순위이며 텍스트 입력부터 시작한다. 별도 프런트 프레임워크 도입은 P0 이후 필요에 따라 결정한다.
- ESP32는 Arduino C++, 첫 통신은 USB Serial JSON Lines. 차우진이 실제 보드/드라이버/빌드 환경을 기록한다.
- 관측 입력은 MockAdapter부터, ReplayAdapter/SerialAdapter로 교체한다.
- 한 기종·한 화구·화력 증가 안내, 검증/복구 Skill 2개가 첫 구현 범위다.
- LLM은 provider 인터페이스 뒤에 둔다. 윤도훈이 팀에서 사용 가능한 계정/키를 확인해 실제 제공자와 모델을 설정한다. 없는 키를 만들거나 비용 결제를 자동으로 하지 않는다.
- 세션 상태는 메모리, 검토 가능한 실행 기록은 JSON Lines. 처음부터 DB·클라우드·배포를 필수로 만들지 않는다.

기술 참고: [FastAPI 공식 문서](https://fastapi.tiangolo.com/), [Espressif Arduino ESP32 공식 문서](https://docs.espressif.com/projects/arduino-esp32/en/latest/).

## 공통 Python 경계

권희원은 Observation, Goal, Verdict, RunEvent 타입을 backend/app/contracts/에 만든다.
Goal: zone_id, direction(increase), requested_steps(1). 이 값은 사용자 의도이고 센서 정답이 아니다.
Observation은 docs/인터페이스.md의 필드를 따른다. 어댑터는 기준 조회, 조작 이후 대기, 상태 조회를 제공한다.
Verifier는 Goal/기준/후속 관측으로 Verdict(status, reason_codes, evidence_ids)를 반환한다.
정확한 한 단계 보정이 없으면 output_change 확인과 exact_step 성공을 분리한다. [판정기준](판정기준.md)이 단일 기준이다.
Agent는 어댑터/Verifier를 주입받고 화면은 Agent API만 사용한다. 화면에서 성공 판정/재시도를 구현하지 않는다.

## 첫 API 계약 (상세는 실행계약 v0.2)

- POST /api/runs: {user_input, source, zone_id} → {run_id, status}. source는 서버 허용 설정으로 검증한다.
- GET /api/runs/{run_id}: 상태·현재 안내·events 반환. 화면은 첫 구현에서 주기 조회한다.
- POST /api/runs/{run_id}/ack: {action_id} → 입력 수신 확인. 사용자의 조작 완료 알림일 뿐 성공 증거가 아니다.
- 상태/API/동시 실행/취소/알림/시간 초과는 [실행계약](실행계약.md)을 따른다. awaiting_clarification도 포함한다.
- 이벤트: event_id, run_id, action_id, timestamp, kind, source, message, evidence_ids. kind는 plan/instruction/tool_call/observation/verdict/recovery/error.
- 정상 API와 Tool 오류는 별도 처리한다. request 오류는 {code,message}, LLM/센서 오류는 실행 이벤트와 상태로 드러낸다.

Mock 시나리오 선택은 로컬 개발 전용 설정에 두며 Agent 이벤트/입력에 정답 라벨을 노출하지 않는다.
화구가 지정되지 않거나 모호하면 사용자에게 확인한다. 실측 대상 화구만 안내한다.

## 운영 기본값

모의 관측 시간창 3초, 추가 물리 재조작 안내는 최대 1회. 설정에서 변경 가능하며 실측 검증된 수치로 주장하지 않는다.
실제 시간창은 저출력 주기 측정 후 결정한다. 시간은 장치 세션 내 단조 시간과 호스트 수신 시간으로 기록하고 동기화/매핑 품질을 표시한다.
자동 시간 동기화를 가정해 서로 다른 시계를 직접 비교하지 않는다.
전송 타입/단위는 [인터페이스 v0.2](인터페이스.md)와 JSON 예시를 사용한다. 첫 티켓은 이를 코드 타입으로 옮기며 계약을 임의로 재설계하지 않는다.
안전 온도 임계값은 현재 정의하지 않는다. P0에 잔열 안전 완료 주장을 넣지 않는다.

## 첫 검증 범위

정상/관측 없음/지연 도착/중복 이벤트/센서 이상/보정 없음/재시도 소진을 확인한다.
실제 LLM 실행은 외부 호출 없는 규칙 검증과 분리하며 모델·설정·토큰·실행 버전을 기록한다.
공식 제출 일정과 실물 장비 확보는 준비 작업으로 진행하고 모의 개발을 막지 않는다.
