# 이름으로 시작하는 역할 분담

기준일 2026-10-05. 사용자 제공 명단에 맞춘 작업 배정이다. 개인 경험을 추정하지 않았다.
구현 경로와 기본 기술은 [구현기준](구현기준.md), 티켓 상태는 [작업현황](작업현황.md)이 기준이다.
이 문서의 경로는 앞으로 만들 파일의 책임 범위이며 코드가 이미 존재한다는 뜻은 아니다.

## AI에게 입력하는 방법

저장소 C:\TouchBack을 열고 다음처럼 입력한다.

> 나는 임민혁이야. 내 다음 작업 진행해.

다른 사람은 이름만 바꾼다. AI는 다음 순서를 따른다.

1. 공통프롬프트·CONTRIBUTING·이 문서·구현기준·작업현황을 읽는다.
2. 이름에 해당하는 미완료 티켓 중 선행 조건을 충족한 가장 앞 티켓을 선택한다. 진행 중인 작업은 기존 변경부터 확인한다.
3. 이름·티켓·변경할 파일·완료 조건을 짧게 알리고 작업 브랜치에서 수행한다. 담당 밖 변경은 아래 공동 변경 규칙을 적용한다.
4. 실제 코드와 검증 근거를 보고 완료 상태로 갱신한다. 물리 구매·배선·실측은 AI가 대신 했다고 쓰지 않는다.
5. 사람의 동작이 필요하면 준비 자료를 완성하고 '물리 작업 대기'로 기록한다. 의존성과 무관한 다음 준비 작업은 계속할 수 있다.
6. 구현완료와 리뷰승인·병합을 구분한다. AI가 팀원 승인란을 채우거나 임의로 PR을 병합하지 않는다.

## 전체 책임

| 이름 | 주 책임 | 기본 리뷰어 |
|---|---|---|
| 임민혁 / 전자 | 센서 선택·회로·외부 설치·실측 조건 | 차우진 |
| 차우진 / 전자 | ESP32 수집·신호 요약·USB 전송·장치 상태 | 임민혁, 관측 계약은 권희원 |
| 권희원 / 컴공 | 공통 데이터 계약·모의/실제 어댑터·검증 Skill·백엔드 기본 틀 | 윤도훈, 전송 계약은 차우진 |
| 윤도훈 / 컴공 | LLM Agent·Tool 연결·오조작 복구 Skill·실행 상태 | 권희원 |
| 김민찬 / 컴공 | 사용자 화면·앱 연결·실행 안내·통합 Demo와 제출 정리 | 윤도훈 |

문서/명세 작성도 구현의 일부이며 맡은 기능의 근거를 담당자가 남긴다. 통합 버그는 발생 계층 담당자가 고친다.
김민찬은 통합과 제출을 정리하지만 다른 네 사람의 코드·측정·설명까지 대신 완성하는 담당자가 아니다.

## 임민혁 — 센서·회로·설치

### 해야 할 일과 순서

- E-MH-01: 견적서 구매 구성은 확정됐다. docs/센서선정.md를 기준으로 hardware/BOM.md에 보유/주문/배송/수령 상태와 부족한 ESP32·주변부를 정리하고 접근 가능한 인덕션을 확인한다. 새 부품 후보 선정부터 반복하지 않는다. 회로·실측 검증은 아직 남아 있다.
- E-MH-02: 선정한 부품의 연결도, 입력 보호·신호 처리, 설치 위치/방향, 측정 절차를 정리한다. 차우진에게 입력 종류·핀/전압 조건·샘플링 요구를 전달한다. 검증 없이 코일을 ESP32에 직결하지 않는다.
- E-MH-03: 사람이 한 기종·한 화구에서 OFF/유지/증가를 반복 측정한다. 기종·냄비·설치·환경·반복 횟수와 원시 기록을 남긴다. 구분 가능한 변화와 실패 조건을 정리하고 권희원에게 보정 근거를 전달한다.

### 수정 범위와 산출물

- docs/센서선정.md, hardware/BOM.md, hardware/wiring.md, hardware/mounting.md, hardware/measurement-protocol.md.
- data/reviewed/의 공유 가능한 비식별 측정 샘플과 설명. 개인 로컬 원시 데이터는 data/raw/에 두고 무조건 커밋하지 않는다.
- AI는 후보 조사·회로 검토 보조·측정 양식/분석 자료를 만든다. 부품 구매, 배선 확인, 설치와 실측은 임민혁이 수행한다.

### 완료 조건

다른 팀원이 부품 목록·연결·설치 조건으로 같은 측정을 재현할 수 있다.
관측 가능한 범위를 데이터로 설명하고, 아직 측정하지 않은 항목을 분리한다.
펌웨어나 Agent의 성공 판정을 임의로 바꾸지 않는다.

## 차우진 — ESP32·센서 이벤트·전송

### 해야 할 일과 순서

- E-CW-01: 실제 보드가 없어도 펌웨어 구조·설정 표·가짜 측정값 생성 모드·USB JSON Lines 출력 예시를 만든다. 권희원과 필드명·단위·순번·재부팅·시간 기준을 맞춘다.
- E-CW-02: 임민혁의 회로/핀 조건을 받아 실제 센서 수집을 연결한다. 자기장 특징과 비프음 횟수를 요약하고 포화/끊김/보정 누락을 품질 코드로 보고한다.
- E-CW-03: USB 연결·분리·재연결·재부팅을 실물로 확인하고 원시 기록과 요약을 비교한다. 임민혁과 설치/감지 조건을 조정한다.

### 수정 범위와 산출물

- firmware/의 Arduino C++ 코드·설정 예시·README·장치 출력 예시.
- docs/인터페이스.md의 장치 출력 부분은 권희원과 공동 관리한다.
- 하드웨어 미확보 시 mock 출처를 명시한다. 보드 확인 전 핀맵/ADC 성능을 확정하지 않는다.

### 완료 조건

한 줄에 하나의 관측을 보내고 세션·순번·측정 시간·출처·품질을 누락하지 않는다.
재부팅/분리/포화가 정상 0으로 위장되지 않는다. 빌드 확인과 실물 업로드 확인을 구분해 기록한다.
인덕션 성공 여부와 사용자의 다음 행동은 펌웨어에서 결정하지 않는다.

## 권희원 — 데이터·어댑터·의도 검증

### 해야 할 일과 순서

### 수정 범위와 산출물

- skills/intent-output-verification/, backend/tests/의 해당 검증, docs/인터페이스.md.

### 완료 조건

누락·오래된 값·부적합 보정에서 성공을 선언하지 않고 근거를 반환한다.
정확한 단계가 검증되지 않으면 단지 출력 변화만으로 '정확히 한 단계' 성공을 반환하지 않는다.
센서 판정과 Agent의 재계획/안내 문구 책임을 분리한다.

### 완료 조건

Tool 호출과 판단·재계획 근거가 남고 정상/미인식 후보/불확실의 전체 경로가 실행된다.
실제 LLM이 목표/Tool 선택 또는 재계획에 참여하는 실행 근거가 있다. 고정 분기나 모의 모델만으로 AI Agent 구현 완료라고 쓰지 않는다.
관측 유효성·안전 규칙을 LLM 판단으로 우회하지 않는다. 한 번의 늦은 응답을 두 번의 물리 조작 안내로 바꾸지 않는다.

### 수정 범위와 산출물

- frontend/의 정적 화면·API client·화면 fixture, tests/integration/, docs/Demo실행.md, docs/검증결과.md.

### 완료 조건

사용자가 목표를 입력하면 백엔드 실제 실행 상태와 안내를 볼 수 있다. UI fixture 성공이 서버 성공으로 표시되지 않는다.
다른 팀원이 README로 실행할 수 있고 영상의 기능과 입력 출처가 코드에서 재현된다.
발표 준비는 마지막에 몰지 않고 각 기능 완성 시 증거를 수집한다.

## 공동 파일과 충돌 방지

| 공동 영역 | 책임자 | 관련 변경의 확인자 |
|---|---|---|
| docs/인터페이스.md, backend/app/contracts/ | 권희원 | 차우진(센서), 윤도훈(Agent), 김민찬(API 소비) 중 영향 받는 담당자 |
| backend/app/main.py, 의존성/환경 예시 | 권희원 | 윤도훈 |
| plan, 작업현황 | 티켓 담당자 | 해당 PR 리뷰어 |
| 공통프롬프트, 역할/구현 기준 | 변경 제안자 | 영향을 받는 담당자 |

파일 소유권은 수정 금지가 아니라 충돌과 계약 변경을 알리는 기준이다. 담당 밖 버그는 재현·영향을 먼저 남기고 필요한 변경을 최소화한다.
PR마다 작성자 외 팀원 1명 이상이 승인해야 한다. 관측 계약 변경은 차우진·권희원 양쪽의 확인이 필요하며 둘 중 작성자가 아닌 쪽은 승인 리뷰를 한다.
승인 전 추가 변경은 다시 리뷰받는다. 병합/배포/구매를 이름 입력만으로 자동 수행하지 않는다.

- E-MH-04 / 임민혁: 2화구/제조사 2종/냄비 3종 설치·측정 조건, IR/진동 부품과 주변부 설계. hardware/의 조건표와 회로를 갱신한다. 확보 불가능한 조건은 미검증으로 기록한다.
- E-CW-04 / 차우진: 주파수/듀티/탐색 펄스·IR·다채널 이벤트와 진동 출력 지원. firmware/와 관측 계약을 확장하고 가능한 특징만 실제 측정으로 검증한다.
- C-KH-05 / 권희원: 기종 자가보정/단계 추적/화구 융합/재동기화/재보정과 안전 검증을 backend/app/verification/ 및 관련 상태 모듈에 구현한다. 실제 구현한 재사용 기능의 Skill 디렉터리를 만든다.
- C-YD-05 / 윤도훈: 복구를 종료만 하는 경로에서 기준 상태 재확보→재보정→재개로 확장한다. 타이머/레시피·개인화·잔열 안내 Tool을 연결하고 결정론적 안전 판정을 유지한다. 실행계약 변경을 함께 검토한다.
- C-KM-05 / 김민찬: P0와 병렬로 사용자 인터뷰/동의·익명화 계획을 준비한다. 구현 뒤 비프만/카메라/TouchBack 비교를 수행하고 확인 행동·도움 요청·시간·오류·한계를 docs/검증결과.md에 기록한다. 실제 모집/평가 수행과 준비 자료를 구분한다.
- C-KM-06 / 김민찬: 음성 입력/진동 안내·복구/잔열/2화구 표시를 확장한다. 권한 거부·지원 불가·음성 반복 방지와 화면 없이 안내를 이해하는 흐름을 검증한다.

위 티켓은 원문 기능 묶음이므로 착수 시 한 PR에서 다 구현하지 않고 측정/계약/기능 단위로 하위 티켓을 나눈다.
본선 증거 취합 C-KM-04는 각 티켓의 실제 완료/미완료·제외 이유를 함께 모은다. 원안 기능을 자동으로 제외하지 않는다.

## 2026-10-08 멘토 피드백에 따른 우선순위

전자팀은 확정 부품의 최소 관측 제공을 준비하고 컴공팀은 실제 LLM + Mock 센서로 Agent 경로를 먼저 완성한다. 역할과 공동 계약은 유지한다.
윤도훈은 실제 모델의 목표 이해·Tool 선택·재계획과 토큰 기록, 권희원은 관측/검증 Skill·Mock 오류 사례, 김민찬은 세 시나리오와 출처/계획/복구 기록 표시를 우선한다.
하드웨어 도착·IR·진동 확장 완료를 Agent 개발의 선행 조건으로 추가하지 않는다.
