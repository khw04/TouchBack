# 평가 기준과 Demo 증거

근거: 평가 안내 1~2쪽, 제안서 8~11쪽. 전체 기능보다 실제 작동하는 핵심 Agent/Skill을 우선한다.

| 항목 | 배점 | 준비할 증거 |
|---|---:|---|
| 고객 문제와 구현 결과 | 20 | 조작 결과 확인의 어려움, 구현이 해결하는 부분과 한계 |
| AI Agent 구조 | 20 | 사용자/Agent 역할, 입력→판단→Tool/Skill→출력, 재계획 기록 |
| 실제 작동과 Demo | 10 | 실제 입력부터 판정·복구까지 끊기지 않는 실행 |
| 핵심 기능·Skill | 30 | 실행 코드, skills/<name>/SKILL.md, 재현 가능한 실행 방법 |
| 기대효과·확장 | 20 | 측정 근거와 확장 계획; 현재와 미래 구분 |

## 대표 시나리오

1. 사용자가 “오른쪽 화구 화력 한 단계 올려줘”를 입력한다.
2. Agent가 목표와 화구를 정하고 터치를 안내한다.
3. Tool이 조작 전후 관측을 반환하고 검증 Skill이 근거를 비교한다.
4. 정상 시 확인된 결과를 안내한다.
5. 미인식 후보 시 원인 확인·재안내·재관측·재검증으로 이어진다.
6. 센서 이상/낡은 관측이면 불확실 또는 중단을 안내한다.

실시간 센서, 모의, 녹화 재생을 화면과 영상에서 표시한다. 실제 평가에서 모의 입력만으로 충분한지는 안내에 명시되지 않았다.
모의 입력은 Agent 개발 증거로 쓰고 실제 인덕션 동작 증거와 분리한다.

## 검증 기록

시나리오/입력 출처/기종/냄비/설치/보정/시도 수/성공·오류·불확실 수/지연/판정 근거/실행 버전을 저장한다.
정답은 [실측평가절차](실측평가절차.md)에 따라 표시 단계와 별도 기록으로 확보한다. Agent에 전달하지 않는다. [판정기준](판정기준.md)의 확인 수준별로 분모/불확실/오성공을 집계한다.
제안서 목표인 터치 판정 98%, 단계 정확 95%(±1 99%), 지연 ≤1초, 재동기화/센서 이상 감지 95% 등은 **목표**다.
현재 실측 성능은 없다. 달성 여부는 검증 후 별도 결과 문서로 기록한다.

## 토큰 절감 가산점

배점 미확정. 원시 데이터 대신 요약, 재사용 가능한 관측, 규칙 처리, 중복 호출 억제를 설명한다.
동일 시나리오에서 모델/설정/호출 수/입력·출력 토큰을 기록하고 비교 기준을 공개한다. 추정 절감률을 실측처럼 쓰지 않는다.

## 제출 체크

- 발표 자료(PPT/PDF/HTML 등)에서 문제·구조·핵심 기능·실측 효과·한계 설명.
- Demo 영상의 기능이 제출 코드에서 확인되고 실행 가능함.
- 전체 소스 ZIP + 실행 README, 설정 예시, 구현한 Skill 디렉터리 포함.
- 다른 팀원이 실행 순서와 실패 시 안내를 확인함.
- 미구현 확장과 구현된 기능을 분리하고 민감 정보 제거.
- 공식 마감·영상 길이·발표 시간 확인. 제안서의 10/28은 공식 확인 전 일정 초안.
