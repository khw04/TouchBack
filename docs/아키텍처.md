# Agent·Skill·Tool 구조

## 실행 흐름

사용자 목표 → Agent 계획 → 조작 안내 → 사용자의 터치 → 관측 Tool → 유효성 검사 → 의도 검증 Skill → 성공/불일치/불확실.
불일치에서는 복구 Skill이 후보 원인과 다음 행동을 정하고 재관측·재검증한다. 안전/센서 문제에서는 임의 반복을 멈춘다.

입력 어댑터는 mock / replay / live를 같은 관측 계약으로 제공한다.
센서·펌웨어는 원시 데이터를 요약한다. 규칙 코드는 품질·시간·보정·안전 제한을 처리한다.
LLM은 목표 해석, Tool 선택, 설명과 재계획을 맡는다. 단순 분류만 수행하는 센서 대시보드로 끝내지 않는다.

## Tool 계약 초안

| Tool | 역할 | 현재 상태 |
|---|---|---|
| read_field(zone_id) | 자기장 요약과 품질 조회 | 제안서 정의, 미구현 |
| await_touch_result(action_id, window) | 조작 이후 시간창의 관측 대기 | 제안서 기반 계약 초안 |
| check_sensor_integrity() | 연결·포화·시간·보정 상태 조회 | 제안서 정의, 미구현 |
| speak / listen | 안내 출력·사용자 목표 입력 | 제안서 정의, 텍스트부터 구현 가능 |
| read_surface_temp / haptic / start_timer | 잔열·진동·시간 안내 | 후순위, 미구현 |

각 Tool은 유효 관측 또는 명시적 오류를 반환한다. 센서 오류를 정상값 0으로 바꾸지 않는다.
물리적인 '화력 증가' Tool은 없으며 사용자 안내와 결과 관측을 분리한다.

## 핵심 Skill의 구현 계약

- intent-output-verification: 목표·기준 관측·후속 관측을 받아 success/mismatch/uncertain과 근거를 반환한다.
- misoperation-recovery: 불일치/불확실·시도 이력을 받아 추가 관측/재안내/중단을 선택하고 다시 검증한다. 늦게 들어온 첫 조작 결과를 확인한 뒤 재조작을 안내한다.
- 후순위: auto-calibration, state-resynchronization, sensor-recalibration, residual-heat-safety.

현재는 설계 명칭이며 실제 skills 폴더가 없다. 구현 시 skills/<name>/SKILL.md를 만들고 목적·입출력·사용 조건·실행 방법·실패 처리·예시를 적는다.
실행 코드와 연결하고 필요할 때 scripts/references/examples/assets를 추가한다. 문서만 만든 Skill을 구현 완료로 세지 않는다.

## 제안서 역할을 작업 경계로 사용

| 분야 | 작업 |
|---|---|
| 임민혁 / 전자 | 센서 후보/픽업 코일/AFE/배치, 원시 신호 품질 |
| 차우진 / 전자 | ESP32 수집·시간·요약·통신·상태 감지 |
| 권희원 / 컴공 | 관측 계약, 어댑터, 융합/상태/보정과 평가 데이터 |
| 윤도훈 / 컴공 | Agent 계획/Tool/Skill/복구와 실행 기록 |
| 김민찬 / 컴공 | 접근성 안내/화면/평가/영상·발표 |

정확한 작업 순서·파일·완료 조건·리뷰 연결은 [역할분담](역할분담.md)을 따른다.
