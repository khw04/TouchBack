# 관측 수집·저장 도구 (C-KH-04 준비)

SerialAdapter의 기존 v0.2 검사·중복/순번·재부팅·출처 검사를 통과한 호스트 Observation을 지속 저장한다. 백엔드 버퍼 256개 제한 때문에 긴 기록이 잘리지 않도록 수신 시점에 저장한다. 인덕션/ESP32에 명령을 보내거나 실제 Agent를 실행하지 않는다.

## 실행

저장소 루트에서 Python 3.12 가상환경과 backend/requirements-dev.txt 설치 후 실행한다. 모듈 경로 지정은 다음처럼 backend 폴더에서 한다.

```powershell
cd C:\TouchBack\backend
..\.venv\Scripts\python.exe -m app.recording.capture --port COM3 --baudrate 115200 --duration 30 --device-id esp32-01 --output-dir ..\data\raw\trial-001
```

COM3·장치 ID는 실제 펌웨어 값에 맞춘다. 기본 속도 115200은 개발 기본값이고 실물 검증값이 아니다. `--duration`은 0초 초과~3600초, 기본 30초다. Ctrl+C는 중단 상태로 저장하고 포트를 닫는다. 출력 디렉터리는 매번 새 경로여야 하며 기존 파일/기록을 덮어쓰지 않는다. data/raw/는 gitignore 대상이다. 검토한 샘플만 별도 공유한다.

## 결과 파일

| 파일 | 내용 |
|---|---|
| observations.jsonl | 수신 시각·출처·측정 조건·품질을 포함한 호스트 Observation, ReplayAdapter.from_file로 읽을 수 있음 |
| events.jsonl | 파싱/출처/중복 충돌/순번·세션 변경/끊김/중단 시 부분 프레임 등 오류 코드와 경과 시간. 원시 바이트·키·정답 없음 |
| summary.json | 완료/중단/끊김/실패 상태, 관측 수·오류별 건수, 시작/종료 시각, 속도 및 실측 성능 검증 미수행 표시 |

정상 중복 프레임은 관측에 중복 저장하지 않는다. 내용이 다른 중복은 conflicting_duplicate 오류로 남긴다. 오류 이후 버퍼에서 무효화된 품질을 정상으로 복구하지 않는다. 정상 종료의 포트 닫힘만 disconnected 오류에서 제외한다. incomplete_line은 정상 종료라도 기록한다. Ctrl+C나 끊김 전 저장된 줄은 보존한다.

완료·관측 1개 이상·오류 0건일 때만 종료 코드 0, 그 외는 1이다. 옵션/경로 오류는 2다. summary.json이 없으면 완결된 수집으로 취급하지 않는다. 시스템 강제 종료·디스크 자체의 기록 불가에 대한 저장 보장은 없다.

## 재생과 한계

```python
from app.adapters.replay import ReplayAdapter
adapter = ReplayAdapter.from_file('../data/raw/trial-001/observations.jsonl')
print(adapter.recorded_sources)  # 원래 출처 보존. 반환 관측은 replay.
```

수집 파일은 장치 입력이므로 source=live이지만 clock_quality는 unverified다. 실물 수신·정확도 검증을 수행했다는 뜻이 아니다. 오류 로그와 summary를 함께 확인하며 observations 파일만으로 성공률을 계산하지 않는다. 호스트 JSONL이 8192바이트를 넘으면 저장하지 않고 host_record_too_long 오류를 남긴다. 독립 정답(trial/action·표시 단계)은 별도 파일로 기록하고 Agent/관측 파일에 넣지 않는다.

## 검증 범위

합성 전송에서 분할 프레임·300개 수집/버퍼 초과·중복/충돌·파싱 오류·재부팅·출처 불일치·부분 프레임·중단·끊김·열기 실패·Replay 호환·덮어쓰기 방지를 검사한다. 실제 ESP32·COM 포트·센서·인덕션·시계 오차·live 정확도는 전자팀과 현장에서 검증해야 한다. 기존 Mock 보정으로 live 성공을 허용하지 않는다.
