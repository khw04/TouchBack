# 2026-10-19 리뷰 수정

## PR #31 지연 성공 방향

좌우 기준 100/100 → 최초 변화 없음 → 원래 조작 시간창의 지연 오른쪽 80/왼쪽 100을 실제 어댑터/검증 경로에 주입해 감소 성공과 증가 안내의 모순을 재현했다. 이제 지연 성공 문구도 Goal.direction에 맞춘다. 증가/감소 두 경로 모두 exact_step 성공·재조작 없음·올바른 안내를 검증한다.

## PR #32 필수 점검 실패 차단

후속 #34의 재동기화 차단을 #32 자체에 반영하고, 특정 Tool 이름뿐 아니라 origin=required_preflight 전체 실패가 안내 게시를 막도록 했다. 왼쪽 tracker 무효화와 새 이름의 필수 점검 실패 모두 수정 전 awaiting_user를 재현했고 수정 후 uncertain/안내 없음/활성 잠금 해제를 확인한다.

## PR #33 초기화 응답 유실 복구

초기화 실패로 생긴 확인 대기를 별도로 추적한다. 시연 설정 재조회에서 명시적인 active_run_id=null, 유효한 양쪽 화력, 활성화된 가상 장치가 확인되면 지난 실행·음성·증거를 비우고 현재 서버 화력을 표시한다. 초기화 성공 자체를 추정하거나 5/5를 만들어내지 않는다. 활성 실행·메타데이터 누락/오류·조회 실패에서는 새 실행을 계속 막고 활성 실행은 기존 불러오기 경로로 안내한다. 다른 조작의 응답 유실을 설정 조회만으로 해제하지 않는다.
