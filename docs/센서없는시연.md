# 센서 없는 Agent 시연과 구현 단계

2026-10-17 사용자 결정: 센서 배송 지연으로 현재 개발·시연은 Mock 관측으로 진행한다. 실제 센서 도착을 Agent 개발의 선행 조건으로 두지 않는다. 원안의 실물 검증·다기종·잔열 목표는 후속/미검증으로 보존하며 원본 PDF나 공식 평가 요건을 변경하지 않는다. 센서 없는 시연을 실제 인덕션 정확도 검증으로 발표하지 않는다.

## 단계와 완료 기준

| 단계 | 구현 내용 | 검증과 한계 |
|---|---|---|
| 1. 기존 PR 정리 | #17 종료 오류 시 포트 정리, #16 거부 응답 사용량 보존 후속 | 합성 오류/HTTP 회귀 검사. #18 오프라인 평가 승인 유지. 자동 병합하지 않음 |
| 2. 관측 기반 시나리오 | 실행별 MockAdapter 유지, 정상·복구·센서 오류 및 지연/누락/중복/재시도 소진 | 실제 POST→ack→step 경로. 정답 분기 대신 관측을 기존 Skill로 검증 |
| 3. 운영자 화면 | 기본 API 화면에서 모의 입력 선택·출처/실행 방식 표시 | fixture와 분리, 실행 중 변경 금지, 실제 브라우저 확인 |
| 4. 반복 시연·증거 | 세 경로 반복 실행과 이벤트/사용량 저장 | mock_llm 검사는 비용 없는 모의 모델. real_llm 실행 증거는 별도 확보 |
| 5. 실제 모델 확인 | 로컬 .env의 실제 키·모델로 동일 시나리오 | 키/접근 권한 필요. 실제 호출·토큰·지연 증거 전에는 완료로 쓰지 않음 |

## 서버 실행

설치 후 저장소 루트 PowerShell에서 오프라인 개발 시연을 실행한다. 환경변수는 이 터미널에만 적용된다.

```powershell
$env:TOUCHBACK_EXECUTION_MODE = 'mock_llm'
$env:TOUCHBACK_DEMO_ENABLED = 'true'
$env:TOUCHBACK_MOCK_SCENARIO = 'normal'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

`http://127.0.0.1:8000/`을 사용한다. `?fixture=1`은 브라우저 화면 예시이므로 Agent 시연 주소가 아니다. 실제 LLM으로 바꾸려면 로컬 .env의 키/모델을 준비하고 execution mode를 real_llm으로 설정한다. real_llm 실패를 모의 모델로 몰래 대체하지 않는다. 현재 health.agent_ready=false는 외부 모델·실물 검증 준비 완료를 선언하지 않는 기존 표시다.

기본값은 backend_stub와 demo_enabled=false다. 기존 설치의 동작을 자동으로 바꾸지 않는다. 운영자 제어는 실행 모드가 mock_llm/real_llm이고 플래그가 활성화된 로컬 주소/클라이언트에서만 보인다. 단일 프로세스만 지원한다.

## 시나리오와 예상 결과

| 모의 입력 | 예상 종료 | 재안내 |
|---|---|---|
| normal | succeeded / exact_step | 없음 |
| recovery | 변화 없음→새 기준 관측→새 action→succeeded | 최대 1회 |
| sensor_error | uncertain | 없음 |
| missing | uncertain | 없음 |
| delayed | 지연 관측 확인 후 succeeded | 없음 |
| no_change | 새 기준이 낡아 uncertain | 없음 |
| duplicate | 동일 관측 한 번 처리 후 succeeded | 없음 |
| recovery_exhausted | 재시도에서도 변화 없어 uncertain | 최대 1회 후 중단 |

위 성공은 모두 source=mock에서 합성 보정/관측으로 검증한 결과다. 실제 가열/센서 성공을 뜻하지 않는다. 정상/복구/오류 결과를 API에서 강제로 지정하지 않고 기존 검증·지연 확인·품질·시간창·재시도 제한을 통과시킨다. 시나리오 이름과 정답 라벨은 사용자 요청·LLM 메시지·Agent Tool 스키마에 넣지 않는다.

## 운영자 설정 API

GET `/api/demo`는 비활성/비로컬에서 `{enabled:false}`만 반환한다. 활성 로컬 요청은 source=mock, 실행 모드, 선택된 시나리오·허용 목록, physical_validation_performed=false를 반환한다. 키나 비용 정답은 포함하지 않는다.

POST `/api/demo/scenario`에 `{scenario:"recovery"}`처럼 전달하면 다음 실행부터 적용된다. 계획/조작/관측 중 활성 실행이 있으면 409이며, 현재 실행의 관측 버퍼를 바꾸지 않는다. 비활성·원격·다른 Origin/Host는 403, 잘못된 이름은 422다. 헤더를 위조한 프록시 운영을 지원하는 기능이 아니며 loopback에만 서버를 바인딩한다. 실행 API는 기존 v0.2 입력을 그대로 사용한다.

원래 source가 replay/live인 실행을 Mock 성공으로 바꾸지 않는다. 시연 시 source=mock을 선택한다. live 미지원 거부와 실제 보정/시계 검증 제한은 유지한다. 기존 Serial 수집·독립 평가 도구는 실제 장비가 준비되면 사용하는 별도 준비 코드다.

## 화면에서 진행하기

1. 위 설정으로 서버를 실행하고 기본 주소 `/`를 연다. **모의 관측 시연 설정**이 보이고 `모의 모델 / 모의 관측 / 실물 미검증` 표시를 확인한다. 실제 모델 설정이면 `실제 모델`로 표시된다.
2. **모의 입력**에서 정상 증가, 미인식 후 한 번 복구, 센서 오류 등을 선택하고 **모의 입력 적용**을 누른다. 선택만 바꾸면 아직 서버에 적용되지 않는다. 적용된 이름을 확인한다.
3. 오른쪽 또는 왼쪽 목표와 화구를 맞추고 **실행 시작**을 누른다. 안내는 Agent가 만든 서버 응답이다. 이 모드에서는 실물 인덕션을 조작하지 않는다.
4. **조작 완료 알림**을 누르면 `/ack` 뒤 `/step`으로 모의 관측과 Skill 판정이 이어진다. 복구 시나리오는 새 재안내에 대해 완료 알림을 한 번 더 누른다.
5. 최종 판정·출처·근거를 확인한다. 실행 중 설정은 잠기며 종료 후 다음 입력을 적용할 수 있다. **실행 기록 JSON 저장**은 현재 실행의 서버 이벤트를 보존한다. 실제 센서 정확도 자료는 아니다.

설정 변경 응답이 끊겨 적용 여부를 알 수 없으면 새 실행을 잠그고 **시연 설정 다시 확인**을 요구한다. 기존 fixture 화면은 이 운영자 패널을 사용하지 않는다.
## 반복 실행과 기록

시연 서버를 실행한 상태에서 별도 PowerShell을 연다. 이 CLI는 `mock_llm` 전용이다. real_llm/비활성/원격 주소는 실행 전에 거부하며 프록시 환경변수와 리다이렉트도 사용하지 않는다.

```powershell
$env:PYTHONPATH = 'backend'
.\.venv\Scripts\python.exe -m app.rehearsal --url http://127.0.0.1:8000 --zone right --repeat 3 --output logs/rehearsal-right.jsonl
.\.venv\Scripts\python.exe -m app.rehearsal --url http://127.0.0.1:8000 --zone left --repeat 3 --output logs/rehearsal-left.jsonl
```

기본 순서는 정상→복구→센서 오류이며 repeat는 1~3, 요청별 timeout은 기본 10초(최대 60초)다. 각 실행에서 서로 다른 action 최대 2개와 제한된 상태 조회만 허용한다. 네트워크에서 불명확한 POST 응답을 재시도하지 않는다. 실행 ID를 받은 뒤 오류가 나면 해당 실행만 취소하고 종료 상태를 조회한다. 시작 응답 유실 또는 취소 결과 불명 시 전체 반복을 중단하므로 서버의 활성 실행을 확인한 뒤 수동으로 이어간다. 다른 사용자의 기존 실행을 취소하지 않는다. 서버 설정 변경·실행을 동시에 수행하는 운영자는 한 명만 둔다.

JSONL에 각 case가 끝날 때 서버 snapshot(판정·근거·이벤트·모의 토큰 메트릭), 시나리오/화구, action ID, 지연, 예상 종료와의 일치 여부를 기록하고 flush한다. 기존 파일은 덮어쓰지 않는다. 마지막 `rehearsal_end`가 없으면 도구 중단/부분 기록으로 취급한다. 서버 snapshot을 가짜 성공이나 합성 정답으로 대체하지 않는다. 예상 종료 라벨은 테스트 조건이며 실물 독립 정답/정확도 평가가 아니다. 외부 모델 토큰 사용량 측정도 아니다.

종료 코드 0은 모든 기대 결과 일치 및 원래 시나리오 복원, 1은 실패/차단된 case, 2는 잘못된 설정·출력·접속/초기 확인 오류다. logs/는 git 제외 대상이며 원본 로그·키를 PR에 올리지 않는다. 자동화된 실제 LLM 반복 호출은 이 도구 범위 밖이다.

## 2026-10-18 설정 확인 실패 시 화면 보류

기본 화면은 최초 GET /api/demo가 확인될 때까지 시작 버튼과 form 제출을 막는다. 지연·통신 오류·잘못된 응답은 명시적인 enabled=false와 구분하며, 설정 패널과 재조회 버튼을 보여준다. 기존 실행을 조회해도 설정 미확인 동안 조작 안내·완료 알림·음성 재생을 보류한다. 설정 변경이 적용됐으나 응답을 잃거나 서버 오류를 받으면 미확인 잠금을 유지하고, 후속 409가 와도 이를 해제하지 않는다. 성공적인 설정 조회 또는 적용 응답만 미확인 상태를 해제한다. 별도로 서버 실행의 연결이 미확인이면 설정 조회 성공으로 과거 조작 안내를 다시 보여주지 않는다. fixture는 기존처럼 서버 설정 API를 호출하지 않는다.


## 2026-10-19 화면 개편 PR 1 사용법

기본 화면은 목표 입력·인덕션 모형·현재 안내·서버 진행/결과 요약을 한 화면에 둔다. 상단 **시연 설정**을 열면 기존 모의 입력 선택/적용, 출처·화구·음성 설정과 실행 ID 조회를 할 수 있다. **상세 기록**에는 기존 기술 판정·이벤트·JSON 저장이 있다. 예시 목표 버튼은 문장과 화구를 함께 선택한다.

이번 단계에서는 서버 활성화 설정과 적용 버튼이 여전히 필요하다. 가상 인덕션 그림은 조작할 수 없는 모형이며 센서 수치도 표시하지 않는다. 기존 **모의 조작 확인** 버튼으로 ack→step을 진행한다. 개편 PR 2에서 화면 기반 시연 활성화/즉시 적용, PR 3에서 가상 조작, PR 4에서 실제 처리된 모의 센서 수치를 연결한다. 로그인 연동은 제외하고 API 키 방식으로 실제 모델 검증을 이어간다.


## 화면 개편 PR 2 · 로컬 시연 설정

로컬 기본 화면은 서버 환경변수 조작 없이 시연 설정 패널에서 Mock LLM/실제 AI와 시나리오를 선택해 활성화할 수 있다. POST /api/demo/settings는 loopback 주소·클라이언트와 같은 Origin만 허용하고 활성 실행이 있으면 409로 거부한다. 설정은 프로세스 메모리에만 유지하며 .env/키를 변경하지 않는다. 실제 AI 선택은 서버 API 키 설정 유무만 확인하며 인증·과금 검증 완료를 뜻하지 않는다. 키 없을 때 실제 모드를 거부하고 Mock으로 자동 대체하지 않는다.

활성화 뒤 모의 입력 선택은 즉시 적용된다. 응답을 잃거나 실패하면 시작을 막고 시연 설정 다시 확인으로 실제 적용 상태를 확인한다. 원격/명시 비활성 기본 계약과 fixture 구분을 유지한다. 로그인 연동은 없다.


## 화면 개편 PR 4 · 센서/Agent 표시

센서 패널은 서버 어댑터가 실제 수집한 모의 관측의 비프음 합계·자기장 RMS·해당 action의 원래 기준 대비 차이·품질을 표시한다. 클릭만 하고 아직 수집하지 않은 관측을 인식 완료로 표시하지 않는다. 누락/null은 0이나 성공으로 대체하지 않는다. 재안내 대기 중에는 직전 action 수치를 이전 조작으로 표시한다. RMS 막대는 실제 전달된 모의 수치이며 임의 파형을 만들지 않는다. 가상 장치 화력값과 Agent 판단 근거는 분리한다.

Agent 패널의 최근 3개 항목은 서버 이벤트에서 가져온 실제 Tool/안내/관측/판정/복구 기록이다. 전체 이벤트와 근거 ID는 상세 기록에 남는다. 설정·취소/연결이 미확인인 경우 수치를 최신이라고 주장하지 않고 보류/마지막 관측으로 표시한다. 실제 모델 호출 여부는 실행 모드와 호출 기록으로 확인하며 Mock LLM을 실제 AI로 표시하지 않는다.


## 화면 개편 PR 5 · 전체를 한 번에 시험하기

마지막 브랜치 feat/demo-rehearsal-ready는 개편 PR 1~4를 포함한다. main에 먼저 병합하지 않아도 다음 명령으로 프런트 전체를 시험할 수 있다.

```powershell
cd C:\TouchBack
git fetch origin
git switch feat/demo-rehearsal-ready
git pull --ff-only origin feat/demo-rehearsal-ready
.\.venv\Scripts\python.exe -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000
```

기본 주소 http://127.0.0.1:8000/ 에서 Ctrl+Shift+R. fixture=1은 붙이지 않는다. 최초 시연 설정에서 Mock LLM을 명시적으로 선택하고 적용한다. 실제 AI를 사용할 때는 서버 .env에 API 키·모델을 넣고 재시작한 뒤 실제 AI를 선택한다. 키 설정 표시가 실제 인증/호출 검증 완료를 뜻하지 않는다. 화면이 키를 받거나 저장하지 않는다.

- 정상: 상단 정상 증가 → 오른쪽/왼쪽 예시 → 안내 시작 → 안내한 화구의 가상 + → 5→6, 비프음 1회/RMS 120/기준 대비 +20, 모의 성공.
- 복구: 상단 미인식 후 한 번 복구 → 시작 → 가상 + → 화력 유지/비프음 0/차이 0, 새 재안내 → 같은 화구 + → 모의 성공. 재안내 전에 버튼을 두 번 누르지 않는다.
- 센서 오류: 상단 센서 오류 → 시작 → + → 비프음 확인 불가/자기장 누락/품질 불량, uncertain. 가상 장치 숫자가 바뀌어도 Agent는 성공을 선언하지 않는다.
- 오조작: 증가 요청에서 - 또는 다른 화구 +를 누르면 성공으로 판정하지 않는다. 기존 정책에 따라 uncertain 또는 제한된 재안내가 나온다.
- 결과 후 다시 시연은 같은 목표·시나리오로 새 실행을 한 번 만들고 가상 장치를 5/5로 준비한다. 진행 중·설정/연결 미확인에는 비활성이다. 활성 실행은 먼저 취소한다. 일반 브라우저 새로고침은 서버 실행을 취소하지 않으므로 실행 중 새로고침했다면 설정의 기존 실행 ID 조회로 확인한다.

시나리오는 상단에서 즉시 적용하고 실행 중에는 잠근다. 주요 안내와 결과는 같은 자리에서 바뀌며 설정·전체 기록은 측면 패널이다. 패널은 Enter로 열고 Escape/닫기로 닫으면 초점을 돌려준다. 모든 가상 조작은 키보드 버튼으로도 가능하다. 자동 음성은 모의 시연임을 접두어로 알리고 끄거나 다시 들을 수 있다. 1280×720/1366×768 기본 배율에서 핵심 영역은 스크롤 없이, 모바일/큰 글씨는 세로 스크롤로 내용을 보존한다. 실제 스피커·화면 낭독기·대상 사용자 평가는 미검증이다.

기존 반복 CLI는 scripted 시연 전용이다. 화면 가상 모드가 켜져 있으면 시작 전에 거부한다. scripted 실행이 필요하면 서버를 원래 Mock 환경변수로 다시 시작하고 화면 활성화/가상 조작과 섞지 않는다.


## 센서 그림과 모의 신호 이동

가상 인덕션 아래의 마이크/자기장 센서 그림은 설명용 배치 예시이며 실제 설치 위치·성능 검증 자료가 아니다. 가상 버튼을 누른 뒤 서버가 수집해 응답한 현재 run/action의 Mock 관측 ID가 처음 도착하면, 값과 품질을 확인한 채널만 센서 → Agent 방향으로 약 1.8초 이동 효과를 표시한다. Agent 처리는 이 효과가 끝나기를 기다리지 않는다. 그림의 Agent는 오른쪽 Agent 진행 패널과 같은 처리 주체를 나타낸다.

- 수집 중에는 점선의 대기 효과만 표시하며 데이터 점을 보내지 않는다. 관측이 없으면 전달/성공을 만들어내지 않는다.
- 비프음 0회·자기장 차이 0도 수집한 관측이므로 전달한다. 전달 효과나 선의 연결은 목표 성공 표시가 아니며 최종 판정은 가운데 안내에서 확인한다.
- null/누락 또는 degraded/invalid 품질인 채널은 경고 문구를 표시하고 정상 데이터 점을 보내지 않는다. 재안내 전 관측은 오른쪽 센서 패널에서 이전 조작으로 구분한다.
- 같은 관측의 폴링·재조회로 효과를 반복하지 않는다. 취소/실패/설정 미확인/통신 실패에는 효과를 중단하고, 새 실행 생성 직전 표시를 초기화한다. 다시 확인한 과거 관측은 정적으로 표시한다.
- 운영체제/브라우저의 동작 줄이기 설정에서는 이동·점선 애니메이션 없이 수신 상태와 수치를 표시한다. 모의 출처/모델 구분, 실제 키의 서버 설정, 기존 관측·판정 계약은 유지한다.

기본 배율의 1366×768·1280×720에서 핵심 화면에 세로/가로 스크롤이 생기지 않도록 낮은 화면의 화구 도형과 여백을 조정했다. 큰 글씨·작은 화면은 내용 손실 없이 세로 스크롤을 허용한다.


## 이상한 입력 뒤 409 또는 새로고침 후 진행이 막혔을 때

지원하지 않는 입력은 추가 확인 필요(awaiting_clarification)로 남는다. 현재 화면의 입력 수정하기를 누르면 그 요청을 종료하고 목표를 다시 쓸 수 있다. 새로고침 뒤에는 빠른 입력 옆 진행 중 실행 불러오기를 먼저 눌러 기존 요청을 확인한 뒤 입력 수정하기/실행 취소로 종료하거나 현재 안내를 이어간다. 단일 활성 실행을 보호하는 409는 유지하며 무관한 입력을 조작으로 해석하거나 다른 실행을 자동 취소하지 않는다.

예전 서버라 복구 버튼이 나타나지 않으면 시연 설정의 기존 실행 조회에 로그의 마지막 실행 ID를 입력해 불러온 뒤 취소할 수 있다. 명확화 대기는 120초 뒤 다음 조회/요청에서 기존 규칙대로 만료된다. 수정 버전 적용 시 실행 중인 서버를 Ctrl+C로 종료한 뒤 같은 실행 명령으로 다시 시작하고 브라우저를 새로고침한다. 저장소는 메모리 기반이므로 서버 재시작은 현재 실행을 보존하는 복구 방법과 구분한다.


## 연속 가상 장치 상태

새 요청은 직전 가상 장치의 좌우 화력을 이어받는다. 서버 재시작 또는 명시적 POST /api/demo/device/reset만 5/5로 초기화한다. 초기화는 같은 출처의 로컬 시연에서만 가능하며 활성 실행 중에는 busy로 거부한다. 취소는 장치를 되돌리지 않으며 이미 반영된 가상 조작은 유지한다. 완료된 실행의 스냅샷은 다음 조작/초기화로 변경하지 않는다.

가상 장치의 단계 보정은 source=mock인 합성 프로필이다. 기존 ZoneState가 수신한 기준 관측의 시간·품질·설치·세션·프로필을 확인하고, 해당 기준의 보정 범위로 판정한다. 내부 levels를 모델/Tool 입력으로 제공하거나 실제 센서 단계 정확도로 주장하지 않는다. 초기화 버튼과 양쪽 센서 진단 화면은 후속 화면 PR에서 연결한다.


## 관측 진단과 교정 화면

기본 모의 장치 반응은 정상이다. 다른 화구/반대 방향은 시나리오를 고르지 않고 가상 버튼을 직접 누른다. 상단 장치 반응 메뉴는 첫 입력 미인식·센서 오류·관측 누락·중복 반응 같은 시험용이며 설정명/내부 정답은 Agent에 전달하지 않는다. 좌우 코일의 모의 변화와 단일 마이크 단서를 관측 패널에 표시하고, 전달 애니메이션은 성공 판정과 구분한다.

관측상 다른 화구나 반대 방향의 한 단계 변화가 확인되면 교정 목표 입력 버튼을 제공한다. 버튼은 문장을 입력할 뿐 새 실행을 자동 생성하지 않는다. 문장을 확인하고 안내 시작→해당 가상 버튼 조작→관측으로 교정을 검증한다. 교정이 succeeded로 끝난 경우만 원래 목표 입력을 제공하며, 역시 사용자가 확인 후 직접 시작한다. 원래 입력을 알 수 없는 새로고침 복구에서는 임의의 원래 목표를 만들지 않는다. 다단계/불명확한 변화에는 자동 되돌리기나 다단계 지시를 제공하지 않는다.

시연 설정의 가상 화력 5/5로 초기화는 실행 종료 후 명시적으로 수행한다. 이미 변한 다른 화구는 취소나 새 요청만으로 초기화되지 않는다. 초기화 응답을 잃으면 수치를 5로 만들지 않고 상태 확인을 요구한다. 실제 장비 제어와 실측 정확도 검증은 포함하지 않는다.


## 음성 목표 입력

지원 브라우저에서 음성 입력을 누른 경우만 PC 마이크 인식을 시작한다. 브라우저가 권한을 요청하며 온라인 음성 서비스를 사용할 수 있다([브라우저 API 설명](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)). 결과는 입력란에 초안으로 채울 뿐 실행하지 않는다. 문장을 확인·수정한 뒤 안내 시작을 눌러야 한다. 20초 제한, 권한/서비스 오류, 미지원 브라우저에서는 텍스트 입력을 유지한다. 예시/교정 목표 선택, 직접 입력, 새 실행/설정 작업이 시작되면 수집을 중단하고 늦은 결과를 버린다. 음성 입력은 INMP441의 비프음 관측이나 실제 LLM 호출과 별도 기능이다.
