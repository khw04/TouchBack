# TouchBack 화면 Demo 실행

## 현재 실행 가능 범위

`frontend/`는 실행 API v0.2(`docs/실행계약.md`)에 맞춘 정적 화면이다. `?fixture=1`은 **UI 화면 예시**이며 센서·Agent·서버 판정이 없다. 예시 종료 상태는 `uncertain`이고 서버 성공으로 표시하지 않는다.

```powershell
cd TouchBack
python -m http.server 8765
```

브라우저에서 `http://127.0.0.1:8765/frontend/?fixture=1`을 연다. **화면 연습 시나리오**에서 정상 흐름, 미인식 후 복구, 센서 오류 중 하나를 선택한다. 목표를 입력하고 `실행 시작` → `조작 완료 알림` → 실행 기록을 확인한다. 복구 예시는 새 안내가 나오면 다시 한 번 `조작 완료 알림`을 누른다. 세 예시를 끝까지 진행한 결과는 `uncertain`이며 실제 센서 판정이나 서버 성공을 뜻하지 않는다. 음성이 지원되지 않으면 화면에 표시되며 같은 안내는 새 event/action에서만 자동 재생된다. `안내 다시 듣기`는 사용자가 직접 누른 경우에만 재생한다.

화면 연습에서 왼쪽 화구를 안내하려면 입력 문장과 화구 선택을 모두 왼쪽으로 맞춘다. 서로 다르거나 화력 증가가 아닌 요청이면 조작 안내를 멈추고 목표 확인 문구를 표시한다.

## 백엔드 연결

권희원/윤도훈의 v0.2 서버가 `frontend/`를 같은 출처에서 제공한 뒤 `http://<서버>/frontend/`를 연다. 별도 개발 서버를 쓰면 `?api=http://127.0.0.1:8000`을 붙이고 백엔드 CORS 허용이 필요하다. 화면은 `POST /api/runs`, `GET /api/runs/{id}`, `POST /ack`, `POST /cancel`만 호출한다. `/api/session`인 1차 제출 API는 계약이 달라 자동 연결하지 않는다.

새로고침 후 이미 발급된 실행 ID가 있다면 `기존 실행 다시 확인`에서 ID를 입력한다. 이 동작은 GET만 수행하며 기존 기록을 자동 음성으로 다시 읽지 않는다. 응답의 ID·상태·실행 방식·출처·이벤트 형식이 계약과 다르면 오류로 표시한다. 서버가 `succeeded`를 반환해도 `exact_step` 확인, 목표 충족, 관측 근거 ID가 빠지면 `성공 근거 부족`으로 표시한다.

조회나 조작 알림 요청의 결과를 확인할 수 없으면 이전 안내·판정 대신 상태 확인 문구를 표시한다. `상태 다시 확인`이 성공하기 전에는 새 실행, 추가 조작 알림, 이전 안내 재청취를 하지 않는다.

시연 순서는 목표 입력 → 서버의 계획/안내 → 사용자 실제 조작 → 조작 완료 알림 → 관측/판정/복구 이벤트 → 종료다. `ack`는 성공이 아니라 조작 완료 알림이다. 화면 상단에서 `source`(mock/replay/live)와 `execution_mode`(backend_stub/mock_llm/real_llm)를 함께 확인한다. `backend_stub`에는 준비 미완료 상태를 표시해야 한다.

## 통합 촬영 체크

화면 연습은 영상 동선과 문구를 확인하는 용도다. 아래 확인 항목은 실제 API와 장치가 연결된 **통합 실행**에서만 완료로 표시한다.

1. **정상:** 새 run ID, 조작 안내, tool_call/observation/verdict, 종료 상태가 모두 보이는지 확인한다.
2. **미인식 후 복구:** 첫 verdict와 recovery, 새 action ID, 두 번째 관측/판정을 확인한다. 같은 안내의 자동 음성 중복이 없어야 한다.
3. **센서 오류:** 오류 근거와 `uncertain`/`stopped`를 확인한다. 성공 화면 또는 재조작 강요가 나오면 이슈로 등록한다.

각 실행에서 입력 출처, 실행 방식, 서버 버전/커밋, 시나리오, 장치·보정 조건, 화면 영상 파일, 이벤트 ID를 기록한다. fixture 실행과 live 실측은 별도 표로 관리한다. 실제 인덕션은 사람이 조작하고 안전 확인도 사람이 수행한다.

화면의 `실행 기록 JSON 저장`은 현재 조회된 run과 이벤트, 입력 요청, 저장 시각, 마지막 서버 확인 시각의 파일 저장을 요청하고 동일한 JSON을 화면에도 표시한다. 인앱 브라우저에서 다운로드가 제한되면 표시된 내용을 선택해 복사한다. 파일의 `classification`이 `ui_fixture`이면 화면 연습, `backend_stub`이면 준비용 응답, `server_response`이면 서버에서 받은 화면 저장본이다. `snapshot_freshness`가 `stale_or_unverified_snapshot`이면 연결이 끊기거나 요청 결과가 불확실한 상태에서 저장한 마지막 값이다. 어느 파일도 장치 실측이나 정답 검증을 대신하지 않는다. 입력 문장이 포함되므로 팀과 공유하기 전에 내용을 확인한다.
