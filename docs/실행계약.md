# 실행 API·상태 전환 v0.2

권희원은 공통 타입/서버 골격, 윤도훈은 이 계약의 실행 API·상태 머신, 김민찬은 클라이언트를 구현한다.
최소 API를 Agent/복구 완료 전 제공한다. backend_stub 모드는 개발용이며 고정 성공 반환을 금지한다.

## API

| 요청 | 입력/응답 |
|---|---|
| POST /api/runs | {user_input:문자열, source:mock/replay/live, zone_id:right/left/null}; 201 {run_id,status,execution_mode} |
| GET /api/runs/{run_id} | 200 {run_id,status,execution_mode,source,instruction,verdict,events}; 없으면 404 |
| POST /api/runs/{run_id}/ack | {action_id:문자열}; 200 {run_id,status,accepted:true} |
| POST /api/runs/{run_id}/cancel | 입력 없음; 200 {run_id,status} |

execution_mode: backend_stub/mock_llm/real_llm. 입력 출처와 모델 실행 방식을 별도로 표시한다.
instruction은 null 또는 {action_id,text}; verdict는 null 또는 판정기준의 객체다.
events는 event_id,run_id,action_id(null 허용),timestamp(UTC),kind,source,message,evidence_ids 배열을 갖는다.
kind: plan/instruction/tool_call/observation/verdict/recovery/error. 정답 라벨·키·원시 대용량 센서 로그는 넣지 않는다.
오류 응답은 {code,message}. validation=422, unknown_run=404, busy/stale_action/terminal_run=409.

## 동시 실행과 확인 알림

P0에서는 서버 전체에 활성 물리 실행을 하나만 허용한다. run_id가 달라도 같은 장치에 동시 안내하지 않는다.
생성·락 획득은 원자적으로 처리한다. 종료 상태에서 락을 해제한다.
같은 action_id의 ack 반복은 성공 응답으로 동일하게 처리하고 새 조작을 만들지 않는다.
이전 action_id의 ack는 stale_action. 종료 실행의 새 ack는 terminal_run.
cancel 반복은 멱등이다. 취소는 관측·재안내를 중지하며 인덕션을 끄는 명령이 아니다.
현재 출력/안전 상태가 확인되지 않음을 알리고 사용자가 직접 상태를 확인하도록 안내한다.
P0는 단일 서버 프로세스이며 다중 worker 운용은 지원하지 않는다.

## 상태 전환

| 현재 | 조건 | 다음 |
|---|---|---|
| planning | 모호한 화구/목표 | awaiting_clarification |
| awaiting_clarification | 사용자 취소/120초 경과 | stopped |
| planning | 목표 해석·기준 관측 완료, 안내 게시 | awaiting_user |
| awaiting_user | 현재 action ack | observing |
| awaiting_user | 60초 미응답 | stopped |
| observing | 검증된 목표 충족 | succeeded |
| observing | 증가만 확인하고 정확 단계 미확인 | uncertain |
| observing | 유효한 변화 없음, 재안내 가능 | recovering |
| observing | 품질/시간/보정 문제 또는 미분류 | uncertain |
| recovering | 지연 관측 재확인, 재안내 조건 충족 | awaiting_user (새 action_id) |
| recovering | 늦은 관측으로 목표 충족 | succeeded |
| recovering | 지연이 불명확하거나 재시도 소진 | uncertain |
| 비종료 상태 | 취소/장치 재부팅·분리 | stopped |
| 비종료 상태 | 처리 불가능한 내부/모델 오류 | failed |

P0 명확화는 추가 문구를 안내한 뒤 현재 run을 cancel하고 새 입력으로 생성한다. 미해결 상태에서 조작 안내를 게시하지 않는다.
종료: succeeded/uncertain/stopped/failed. 종료 후 관측은 분석용으로 남기되 실행 결과를 바꾸거나 음성을 재생하지 않는다.
도구 오류/품질 문제가 있어도 변화 없음으로 간주해 재조작을 안내하지 않는다.

## 시간·복구 기본값

mock 관측 3초, ack 기다림 60초, 명확화 120초, 재조작 안내 최대 1회.
live는 검증된 보정의 관측 시간창을 사용하고 값이 없으면 uncertain으로 끝낸다.
첫 안내 직전의 기준 관측과 그 뒤 관측을 버퍼링한다. 종료 시각은 ack+관측 시간창이다.
복구 전에 원래 조작의 지연 관측을 확인하며 전송 큐/시간 매핑이 불확실하면 재조작을 권하지 않는다.
판별 불가능한 출력 증가에 '한 번 더 눌러라'를 안내하지 않는다. 실제 시도 전 새 기준 관측이 필요하다.

## 필수 검증

동시 생성 두 요청 중 하나만 활성, ack 중복/이전 action ack, 취소 반복, 미응답 종료,
종료 뒤 늦은 관측, 재부팅, 보정 누락, 지연 후 성공, 재시도 소진, LLM 오류를 각각 확인한다.
계약 스텁은 backend_stub와 준비 미완료 상태를 반환한다. 스텁 성공을 Agent Demo로 사용하지 않는다.
