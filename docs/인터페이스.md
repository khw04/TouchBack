# 관측 인터페이스 v0.2

이 문서는 장치와 서버 사이의 구현 계약이다. 변경은 차우진·권희원 확인 후 양쪽 코드/예시를 함께 갱신한다.
수치 예시는 mock 데이터이며 실제 장비 사양이나 보정 값이 아니다.

## 장치 출력

USB에서 UTF-8 JSON 객체 한 개 + LF를 전송한다. 로그 문장을 같은 스트림에 섞지 않는다.
한 줄 최대 8192바이트. 초과/비정상 JSON/알 수 없는 버전은 오류로 기록하고 성공 근거에서 제외한다.
정식 예시는 [device-observation.json](examples/device-observation.json).

| 필드 | 타입/규칙 |
|---|---|
| schema_version | 문자열, 현재 0.2 |
| device_id | 비어 있지 않은 문자열, 장치별 고정 |
| session_id | 비어 있지 않은 문자열, 재부팅 때마다 변경 |
| seq | 0 이상의 정수, 같은 세션에서 증가 |
| source | mock/live/replay, 출처 보존; 서버 설정과 불일치하면 오류 |
| zone_id | right/left/unknown, 첫 실측 대상은 설치 설정으로 하나만 등록 |
| window_start_ms/window_end_ms | 장치 부팅 이후 단조 시간 정수; start < end |
| beep_count | 0 이상의 정수 또는 null(미측정) |
| field_summary | 아래 객체 또는 null |
| quality | {status: valid/degraded/invalid, reasons: 문자열 배열} |
| calibration_id | 문자열 또는 null, 설치/기종 보정 식별 |

field_summary: rms는 0 이상 유한 실수, unit은 adc_count 또는 millivolt,
sample_count/sample_rate_hz는 양의 정수, method는 문자열이다.
ac_rms_v1은 각 샘플에서 해당 시간창 평균을 뺀 값들의 RMS다.
AFE가 포락선 출력 등 다른 방식이면 method를 새로 기록하고 보정도 분리한다.
ADC 원시값을 전압/자기장 SI 단위로 위장하지 않는다. 단위/방법/설정이 다른 값을 직접 비교하지 않는다.
온도는 v0.2 필수 항목이 아니다. 추가 시 계약 버전과 단위/유효성을 정의한다.

## 서버가 붙이는 정보

장치는 action_id/run_id를 받거나 생성하지 않는다. 서버가 단 하나의 활성 조작과 시간창을 연결한다.
서버 Observation은 [host-observation.json](examples/host-observation.json) 형식이다.
observation_id = device_id:session_id:seq, run_id/action_id는 연결 불가 시 null.
received_at은 UTC ISO 8601, received_monotonic_ms는 호스트 단조 시간이다.
mapped_window_start_ms/end_ms는 호스트 기준 추정 또는 null, clock_quality는 verified/unverified.
received_at을 장치 시간과 직접 비교하지 않는다. 세션 변경 시 이전 시간 매핑과 기준 관측을 폐기한다.

## 시간 정렬과 조작 연결

1. 첫 연결/재연결 뒤 정해진 5개 연속 관측으로 host_received - device_window_end 차이를 수집한다.
2. mock에서는 가상 시계를 제어해 매핑을 검증한다. live의 위 차이는 지연을 포함한 추정일 뿐이며 unverified로 시작한다.
3. 차우진/권희원이 전송 지연·큐 적체를 측정해 보정 파일에 허용 오차를 기록한 경우에만 verified로 올린다. 코드에서 임의로 verified로 고정하지 않는다.
4. 매핑된 시간창 전체가 해당 조작의 허용 창 안에 있고 zone/session/quality/보정이 맞아야 성공 근거에 포함한다. 경계를 걸치면 uncertain 근거다.
5. 안내 전에 유효한 기준 관측을 얻는다. action_id 생성·안내 게시 직전에 시작 시간을 저장하고 관측을 버퍼링한다. ack 이후에만 수집을 시작하지 않는다.
6. ack는 사람이 조작했다고 알린 시점이며 관측 정답이 아니다. 안내부터 ack 이후 시간창 종료까지 연결하고 늦은 첫 조작 결과를 확인한 뒤 재안내한다.

live 매핑의 신뢰성을 확보하지 못하면 데이터 표시/분석은 가능하지만 자동 성공 확인은 하지 않는다.
정확한 신호 시간창과 전송 지연의 허용값은 실제 측정 후 calibration_id별 설정으로 넣는다.

## 오류와 판정

중복 observation_id/seq는 한 번 처리한다. 순번 역행은 오류, 새 session_id는 재부팅으로 처리한다.
quality reason 예: disconnected/saturated/missing_samples/uncalibrated/clock_unverified/parse_error.
0은 측정값이고 null은 알 수 없음이다. 재생은 원시 출처를 기록하면서 source=replay로 제공한다.
성공 판정은 [판정기준](판정기준.md), 실행/늦은 관측 처리와 기본 시간은 [실행계약](실행계약.md)을 따른다.
Agent 반환에 mock 시나리오 라벨/평가 정답을 포함하지 않는다.

## 원안 신호 특징과 확장 경계

v0.2의 RMS는 첫 관측 계약이며 원안의 주파수·듀티·탐색 펄스/잔열 감지를 모두 제공하지 않는다.
차우진 E-CW-04와 권희원 C-KH-05에서 frequency_hz, duty_ratio, pulse 정보, 화구별 채널, 온도/품질을 확장하고 자료형·방법·단위를 새 버전으로 정의한다.
측정하지 못한 특징을 가짜 값으로 채우지 않는다. mock 예시의 1 kHz는 테스트용이며 원안의 20~100 kHz 신호를 직접 측정할 수 있다는 사양이 아니다.
실제 고주파 측정 또는 포락선/정류 후 저주파 수집 방식은 AFE·샘플링 설계와 보정으로 확인한다.
확장 전에는 냄비 미인식/출력 강하/잔열·2화구 식별을 v0.2만으로 구현 완료했다고 쓰지 않는다.
