# Agent 실행 설정과 검증 계약

2026-10-08. 이 문서는 구현할 설정과 완료 조건이다. 현재 백엔드·설정 로더·실행 명령은 미구현이다.

## 입력과 실행 모드

- 실제 LLM + Mock 센서: 사용자 목표와 테스트 관측으로 Agent 개발. 첫 완료 대상이다.
- 모의 LLM + Mock 센서: 비용 없는 단위/계약 검사. 실제 AI Agent 완료 증거로 쓰지 않는다.
- 실제 LLM + replay/live 센서: 기록 재생 또는 실물 통합. 출처와 실제 성능을 별도로 기록한다.

Mock 센서는 비프음 횟수·자기장 변화·측정 품질 등의 테스트 관측을 반환한다. 시나리오 정답/명칭은 Agent 입력에서 숨기고 평가 측에 둔다. 같은 관측 계약을 사용해 실제 입력으로 교체한다.

## 환경변수

루트 .env.example을 설정 템플릿으로 사용한다. 실제 키는 각 개발 환경의 로컬 .env 또는 서버 환경변수에만 둔다. 환경변수가 파일보다 우선하고 백엔드가 작업 디렉터리에 의존하지 않고 저장소 루트 .env를 읽도록 구현한다.

| 설정 | 값/용도 |
|---|---|
| OPENAI_API_KEY | 실제 키. 예제는 빈 값이며 발급 확인 전 실제 호출 불가 |
| OPENAI_MODEL | gpt-6-luna 초기 기본값. 교체 가능한 설정 |
| OPENAI_REASONING_EFFORT | low 초기 기본값. 성능·지연 검증 뒤 조정 |

OpenAI Responses API의 함수 호출로 Tool 실행을 연결한다. LLM은 목표 이해·계획·Tool 선택·설명·재계획을 맡고 관측 유효성·안전·최대 추가 조작 횟수·성공 허용 조건은 코드에서 검증한다.
Luna는 최종 성능 검증 모델이 아니다. 복잡한 오류 상황에서 부족하면 설정/프롬프트를 확인하고 상위 모델을 동일 시나리오로 비교한다. 지원 한도가 있다는 이유로 자동 결제나 모델 교체를 하지 않는다.

## 오류와 비밀키

키 누락·인증 실패·시간 초과·사용 한도·잘못된 Tool 인수·모델 응답 오류를 명시적 오류로 처리한다. 센서 값을 조작하거나 모의 모델로 몰래 대체해 성공을 반환하지 않는다. 재시도와 취소는 실행계약에 따른다.
키를 브라우저·ESP32·요청/응답 로그·실행 이벤트·PR·영상에 포함하지 않는다. .env는 .gitignore로 제외하고 .env.example만 커밋한다.
개발 도구에서 사용하는 API와 제품 Agent의 호출 기록을 구분하되 같은 지원 계정이면 비용은 합산한다. 팀원별 키와 용도별 구분이 가능한지는 발급 방식 확인 후 정한다.

## 사용량과 완료 조건

지원 한도는 팀 전체 20만 원이며 개발과 Agent 실행 모두 가능하다는 사용자 확인을 기준으로 한다. 실제 지원 공지·키 발급·결제/대시보드 조건은 확인 전 미완료다.
실행별 모델·추론 설정·호출 수·입력/캐시/출력 토큰·출력에 포함된 추론 토큰·오류·지연을 기록한다. 추론 토큰을 출력에 다시 더해 중복 집계하지 않는다. 개발 도구 사용량은 제공자 대시보드와 함께 확인한다.
가격과 환율을 고정된 최신 사실로 넣지 않는다. 측정일의 적용 요금과 기준으로 추정 비용을 기록하고 실제 청구와 구분한다. 최초 1일 사용량 확인 후 남은 기간의 개발/테스트/시연 예산을 배분한다.
실제 LLM + Mock 센서로 정상, 변화 없음 후 제한된 복구, 센서 이상/누락에서 완료 보류를 검증한다. 목표·계획·Tool·근거·재계획·최종 안내가 실행 기록에 남고 고정 성공 분기로 대체되지 않아야 한다.
